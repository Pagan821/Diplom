ТЕХНИЧЕСКОЕ ЗАДАНИЕ на разработку веб-сервиса агрегации онлайн-кинотеатра.
1. Общие сведения
Наименование проекта: Мульти-кинотеатр
Плановые сроки: 11.11.2026 – 31.01.2027

Назначение сервиса: Предоставление пользователю единой платформы для поиска, 
просмотра информации о фильмах и сериалах из различных онлайн-кинотеатров (Кинопоиск, IVI, Okko, Wink и др.), 
а также реализация модели единой подписки, покрывающей несколько сервисов.


2. Цель и задачи разработки
Цель: Создание веб-сервиса, агрегирующего контент из API онлайн-кинотеатров, с единым интерфейсом поиска, каталога и моделью единой подписки.

Задачи:

Реализовать интеграционный слой с API онлайн-кинотеатров (Кинопоиск и минимум один дополнительный).

Реализовать агрегацию и нормализацию данных из разных источников к единому формату.

Разработать модули регистрации/авторизации, каталога, поиска, единой подписки, личного кабинета, сравнения и рекомендаций, настроек.

Реализовать модель единой подписки с оплатой через платёжный шлюз (тестовый режим).

Обеспечить кэширование ответов внешних API и устойчивость к ограничениям (rate limiting).

Развернуть бэкенд с БД PostgreSQL, REST API, WebSocket, S3-хранилищем, доменом и логированием.



3. Требования к функциональности


3.1. Модуль регистрации/авторизации
Регистрация:

Регистрация по адресу электронной почты или номеру телефона.

Подтверждение номера телефона через СМС-код от стороннего провайдера.

Указание пароля и имени пользователя при регистрации.

Валидация введённых данных (формат email/телефона, сложность пароля, уникальность имени).


Авторизация:

Вход по email почте/номеру телефона и паролю.

Восстановление пароля через поддержку и сброс по коду.

Аутентификация на основе JWT-токенов.

Опционально: авторизация через OAuth (Google, VK, Яндекс).

Требования:

Пароли хранятся в хэшированном виде (bcrypt/argon2).

Защита от брутфорса (rate limiting на попытки входа).



3.2. Модуль каталога
Отображение агрегированного каталога фильмов и сериалов из подключённых источников.

Карточка контента: постер, название, описание, рейтинг, жанры, год, актёрский состав, трейлер.

Отображение доступности контента по каждому сервису (подписка/аренда/покупка).

Фильтрация: по жанру, году, рейтингу, источнику, типу (фильм/сериал), доступности по подписке.

Сортировка: по популярности, рейтингу, новизне.

Пагинация или бесконечная прокрутка.

Требования:

Данные получаются из API источников и кэшируются (Redis).

Нормализация данных разных источников к единой модели.

Обработка недоступности источника (graceful degradation).



3.3. Модуль поиска   
Единый поиск по всем подключённым источникам одновременно.

Поиск по названию, актёрам, режиссёрам, жанрам.

Отображение результатов с указанием источника и условий доступности.

История поисковых запросов пользователя.

Ранжирование результатов (релевантность, популярность).

Требования:

Агрегация результатов из нескольких API с дедупликацией.

Кэширование частых запросов.

Ограничение количества запросов к внешним API (rate limiting).



3.4. Модуль единой подписки
Просмотр доступных тарифов единой подписки.

Оформление подписки с оплатой через платёжный шлюз (ЮKassa/Stripe, тестовый режим).

Отображение списка сервисов, покрываемых подпиской.

Управление автопродлением и историей платежей.

Отображение статуса доступа к контенту каждого сервиса.

Отмена и продление подписки.

Требования:

Интеграция с платёжным шлюзом в тестовом (sandbox) режиме.

Хранение истории платежей и статусов подписки.

Обработка ошибок платежей и повторных попыток.

Уведомления о статусе подписки (email/в приложении).



3.5. Модуль личного кабинета
Просмотр и редактирование профиля пользователя.

Раздел «Избранное» (сохранение фильмов и сериалов).

История просмотров и переходов к контенту.

Управление подпиской (статус, продление, отмена).

Настройки уведомлений и конфиденциальности.



3.6. Модуль сравнения и рекомендаций
Сравнение доступности одного фильма на разных платформах.

Рекомендации на основе истории просмотров и избранного.

Подборки: «Популярное», «Новинки», «Скоро выйдет».

Требования:

Базовый алгоритм рекомендаций (на основе истории и избранного).

Обновление подборок по расписанию или при запросе.



3.7. Модуль настроек
Настройки конфиденциальности.

Настройки приложения (тема, язык, уведомления).

Помощь и обратная связь.




4. Требование к бэкенду

4.1. База данных
PostgreSQL.

Схема БД: пользователи, подписки, платежи, контент, связи контента с источниками, избранное, история, поисковые запросы.

Резервное копирование БД и медиафайлов.



4.2. Интеграционный слой
Адаптеры для подключения API онлайн-кинотеатров (Кинопоиск, IVI, Okko, Wink — минимум два источника).

Нормализация данных из разных источников к единой модели.

Обработка ошибок и ограничений внешних API (rate limiting, fallback).



4.3. REST API
Документирование через Swagger/OpenAPI.

Эндпоинты для: аутентификации, каталога, поиска, подписки, личного кабинета, настроек.

Версионирование API.



4.4. WebSocket
Обмен данными в реальном времени: статусы подписки, уведомления, обновление доступности контента.



4.5. Кэширование
Redis для кэширования ответов внешних API и частых запросов.

Настройка TTL и инвалидации кэша.



4.6. Хранилище медиа
Облачное S3-хранилище для постеров, изображений профиля, кэша медиа.



4.7. Инфраструктура
Настройка домена и подключение к серверу.

Мониторинг сервера и логирование ошибок.

Резервное копирование БД и медиафайлов.

Обработка ошибок и логирование (централизованное).



4.8. Безопасность
JWT-аутентификация.

Хэширование паролей.

Защита от SQL-инъекций, XSS, CSRF.

Rate limiting на критичные эндпоинты.

Соответствие требованиям 152-ФЗ (защита персональных данных).



5. Требование к фронтенду
Адаптивная верстка (десктоп, планшет, мобильные).

Главная страница, каталог, карточка контента, поиск, личный кабинет, страница подписки, настройки.

Интуитивная навигация и фильтрация.

Отображение статусов загрузки и ошибок.

Поддержка современных браузеров (Chrome, Firefox, Safari, Edge).

7. Требование к тестированию
Модульное тестирование ключевых компонентов.

Интеграционное тестирование API-интеграций (моки + реальные запросы).

Тестирование сценариев подписки и платежей (тестовый режим).

Юзабилити-проверка интерфейса.

Проверка обработки ошибок внешних API.





8. Ограничения и риски
Риск:							Меры снижения:

Ограничения API Кинопоиска (лимиты, платность)		Кэширование, использование бесплатных тарифов, моки для демонстрации
Юридические ограничения агрегации			Акцент на информационно-поисковом характере сервиса; модель подписки — как концепция/партнёрская схема
Отсутствие официальных API у некоторых сервисов		Использование доступных API, fallback-источники
Сложность реализации единой подписки			Демонстрационная модель с платёжным шлюзом в sandbox-режиме




9. Ожидаемые результаты
Работающий веб-сервис с интеграцией API Кинопоиска и минимум одного дополнительного источника.

Реализованные модули: единой подписки, регистрации/авторизации, каталога, поиска, личного кабинета, сравнения и рекомендаций, настроек.

Развёрнутый бэкенд: PostgreSQL, REST API, WebSocket, S3-хранилище, кэширование, домен, логирование, резервное копирование.

Протестированный и отлаженный сервис, готовый к демонстрации.

Документация API (Swagger/OpenAPI).
